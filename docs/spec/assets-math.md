# T08 asset admission, exact amounts and old-vault recovery

CrossFlow v1 admits only three sorted legacy SPL Token mints committed in the active policy. A mint account must be owned by the legacy token program, have the exact 82-byte base layout, be initialized, match its committed address and 0–9 decimals, and have neither mint nor freeze authority. Token-2022 and its extensions are rejected rather than approximated. Funding, thin settlement and open-intent recovery use the same admission helper. Owner and intent ATAs are derived from the legacy token program and checked for initialized state, exact mint/authority, no delegate, no close authority and no native wrapping.

Raw `u64` amounts are the only transfer authority. The TypeScript display parser accepts exact canonical decimal strings and rejects excess fractional precision, scientific notation, signs and values above the admitted cap. On-chain per-owner input/output caps are `10^12` raw units, and the aggregate pool cap is `3 × 10^12`. Arithmetic uses checked `u64` totals and `u128` products. No floating point or silent rounding is admitted.

For an external output `Y` and three exact input contributions `x[i]`, the future batch path divides `Y*x[i]` by `sum(x)` using integer quotient and remainder. It assigns the leftover raw units to descending remainder, breaking ties by ascending owner pubkey bytes. Zero-input owners receive zero. Every positive input must receive positive output, every output stays within the per-owner cap, and the allocated sum must equal `Y`. If any constraint fails, the whole batch rejects. Rust and TypeScript implement and test the same fixed examples and edge boundaries; T09/T16 must wire this helper into actual venue settlement before claiming routed dust safety.

Unsolicited tokens in an open intent vault remain owner surplus. Settlement excludes them from solver debit, price valuation and approved output bounds. Owner withdrawal takes the selected vault's complete current balance and checks exact deltas; close requires all three vaults empty and returns their rent to the owner. An outside party can recreate a closed old-nonce vault ATA and donate later. `recover_closed_vault` lets only the recorded owner sign for that old PDA's token authority if `nonce < persistent next_nonce` and the old PDA is not the active intent. It requires the exact old intent PDA, canonical vault ATA and canonical owner recipient ATA; it creates a missing recipient ATA with owner-paid rent, transfers the full raw balance, checks exact deltas and closes the vault to return rent. The instruction does not recreate an intent, modify nonce/claim count, check pauses, use an oracle, or use solver/admin authority. The supplied mint need not remain in the current policy, but it must still be a valid immutable legacy SPL mint.

The isolated local T08 transcript funded and closed nonce 0, rotated a zero-claims policy to version 2 with a different cash mint, then recreated and donated 1,000 raw units of the removed old cash mint to nonce 0's vault. Owner recovery returned all 1,000 units and 2,039,280 lamports of vault rent, with the intent remaining closed and next nonce unchanged. Current nonce, non-owner signer, substituted vault/recipient and empty-vault replay each produced named target-program rejection logs. This is synthetic TEST PRICES on a local validator; it does not establish devnet deployment, live equity data, three-owner matching or an external route.
