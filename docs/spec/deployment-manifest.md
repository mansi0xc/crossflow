# T05 deployment identity and configuration contract

Status: implementation input for T05. No configuration initializer, escrow, local CrossFlow transaction or devnet deployment exists merely because this contract is written.

The program must be built for one explicit environment at a time. A public, versioned deployment manifest fixes `program_id`, `genesis` (32 decoded bytes), `deployment_id` (32 public random bytes), `config_address`, `expected_initializer`, `expected_initial_admin`, the exact three fixture assets, the fixture publisher, and `initial_policy_hash`. The config PDA is derived from `[b"config", deployment_id]` and the program ID. The manifest generator recomputes the PDA, canonical policy bytes and SHA-256 itself and refuses mismatches. It emits no private key or seed phrase. The manifest hash, source commit and program binary hash enter T05 evidence.

Build-time code embeds those public values as constants in the reviewed program binary. An absent manifest, different program ID, unsupported cluster/mode, zero identity, unsorted asset list, policy-hash mismatch or an attempt to reuse a devnet manifest on a different local genesis fails the build/preflight. A local validator's genesis is read from the owned ledger after it starts; the local build uses a local-only manifest and disposable signer. The devnet build uses the exact checked devnet genesis and the user's approved CLI wallet public key as expected initializer. Neither build selects identity from a caller-supplied instruction argument. The active manifest is never inferred from the global Solana CLI configuration.

`initialize_config` uses `#[account(init, seeds = [b"config", DEPLOYMENT_ID], bump, payer = expected_initializer)]`, with `Signer` constrained to compiled `EXPECTED_INITIALIZER`. It requires the supplied admin to equal compiled `EXPECTED_INITIAL_ADMIN`; the config/policy/asset/oracle fields and initial policy hash must exactly equal the manifest constants. It stores network/program/deployment identities, policy version 1, pause bits false and outstanding-claim counter zero. Initialization cannot be repeated and does not use `init_if_needed`. An attacker signing first, or a valid signer requesting a different admin/policy, must fail before account creation. T05 tests a pre-funded empty system-owned PDA separately; handling donated lamports must never relax the identity checks or overwrite an initialized config.

The fixture snapshot PDA is `[b"prices", config_address]`. T14 supplies its strict publisher/sequence/timestamp/price checks; T05 binds its account initialization and update instructions to the immutable config and compiled publisher. Funding additionally checks a fresh snapshot with exact owner/PDA/policy/feed identity and stores the accepted funding prices. A fresh wrapper timestamp does not excuse stale underlying stock observations. Pyth mode 1 remains rejected.

The local transaction script must resolve and print all account addresses and human-readable test amounts, make the user-signer role explicit, and check the validator genesis before signing. It records signature, slot, balances before and after, program ID, config/intent/vault addresses and any error; it never logs secret bytes. The script must not send a devnet or mainnet transaction as a fallback when local execution fails. Devnet deployment is a separate later gate after local fund/reject/recover evidence and review.

The 20 devnet SOL budget is sufficient for the planned devnet experiment only after a dry-run rent/fee estimate is compared with the wallet balance. No mainnet fee, paid RPC, Pyth trial or asset purchase is permitted by this contract.

Primary platform constraints: [Solana PDA derivation and signing](https://solana.com/docs/core/pda), [Anchor account constraints](https://www.anchor-lang.com/docs/references/account-constraints).
