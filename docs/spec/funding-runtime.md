# T05 local funding runtime evidence

T05 now builds a manifest-bound config, publishes the documented fixture prices, and funds one selected owner slice through the actual SBF program on a local Solana validator. The public deployment manifest, source-bound run record, transaction signatures, raw balances and limitations are preserved in [T05-local-runtime.json](../../verification/evidence/T05-local-runtime.json) and [T05-local-manifest.json](../../verification/evidence/T05-local-manifest.json).

The local demo proves all of the following on chain: a rent-exempt prefunded config PDA remains system-owned after an attacker initializer is rejected for the expected `Initializer` error; the manifest-authorized initializer can initialize it; duplicate initialization fails because the account is already allocated; and fixture publication advances the exact sequence. Simulated invalid requests must invoke CrossFlow and fail with the expected program error, and the harness confirms source and vault balances remain unchanged after each simulation. Cases include one-raw-unit reference drift, insufficient source amount, substituted source ATA, substituted configured mint, wrong funder signer, a second active intent at nonce 1, and replay of the nonce-0 intent. A separate Rust-host test rejects both a decimals mismatch and a mint identity mismatch.

The confirmed funding transaction moves exactly 100,000,000 cash raw units plus 1,000,000 raw units of each test stock from the owner's canonical ATAs to the intent's derived vault ATAs. The demo decodes the deployed 522-byte intent and checks its canonical 605-byte mandate hash, optimization commitment, all three funding/min/max/reference rows, recipients, vaults, booked claims, and initial surplus against the signed request and independently derived accounts. The owner state records nonce 1 and the active intent.

The successful funding transaction requested 600,000 compute units and consumed 188,730 on this local validator. The transaction includes an explicit Compute Budget instruction before the exact 185-byte funding instruction; the program authenticates the current instruction from the instructions sysvar, so it still rejects CPI invocation and trailing body bytes. No lookup table, Pyth account or settlement CPI was used in this local slice.

These test prices are synthetic and explicitly labelled **TEST PRICES**. The local program is upgradeable under the temporary local validator wallet. No devnet transaction appears in this evidence. Settlement, cancellation, refund and rent recovery remain T06; authenticated stock prices, Pyth and production asset admission remain out of scope for T05.
